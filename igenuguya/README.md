# 이게누구야

카카오톡 친구 중 계속 인연을 이어가고 싶은지 플랫폼이 대신 물어보고, 응답 결과를 바탕으로
본인이 최종적으로 연락처 정리 여부를 판단하는 서비스.

## 핵심 플로우

1. 사용자가 카카오 로그인 → 카카오톡 친구목록 불러오기
2. 정리 대상 친구 선택 + 확인 메시지 작성
3. 플랫폼이 카카오톡 메시지 API로 각 친구에게 확인 메시지 발송
4. 친구가 랜딩페이지에서 원터치 응답 ("계속 연락하고 싶어요" / "정리하셔도 돼요")
5. 대시보드에서 유지 / 정리동의 / 응답대기 현황 확인 → 사용자가 최종 판단

## 로컬 실행

```bash
pnpm install
cp .env.example .env       # 값 채우기
pnpm exec prisma db push   # SQLite(dev.db) 생성
pnpm dev
# http://localhost:3000
```

## 카카오 디벨로퍼스 설정 체크리스트

이 서비스는 일반 카카오 로그인과 달리 **카카오톡 소셜 API(친구목록/메시지 보내기)** 를 사용합니다.
아래 항목이 준비되어야 실제 발송이 동작합니다 (그전까지는 로그인/UI는 동작하지만 친구목록·발송 API는 실패 응답을 줍니다).

1. [developers.kakao.com](https://developers.kakao.com) 에 앱 생성 (또는 기존 앱 재사용)
2. **플랫폼** 탭에 `http://localhost:3000`, 배포 도메인 등록
3. **카카오 로그인 → Redirect URI** 에 `{도메인}/api/auth/kakao/callback` 등록
4. **동의항목**에서 `friends`(카카오톡 친구목록), `talk_message`(카카오톡 메시지 전송) 활성화
   - 두 항목 모두 **비즈니스 앱 전환 + 사용권한 신청/검수**가 필요함 (사업자등록 필요)
   - 검수 통과 전까지는 두 API 모두 401/403 에러를 반환함
5. `.env` 의 `KAKAO_REST_API_KEY`, `KAKAO_REDIRECT_URI` 채우기

## 알려진 제약

- `friends` API는 사용자의 카카오톡 친구 **전체**가 아니라, 그중 **친구목록 제공에 동의한 친구만** 반환합니다.
  즉 카카오 쪽 동의 설정을 안 한 친구는 애초에 조회 목록에 나타나지 않습니다.
- 메시지 콘텐츠("연락처 정리")가 카카오 앱 심사에서 스팸/부정 사용으로 오인되지 않도록,
  심사 신청 시 사용 목적 설명과 예시 메시지를 순화된 톤으로 준비할 것.
- 검수 전 개발 단계에서는 카카오 개발자 계정 본인의 테스트 친구로만 발송 테스트 가능.

## 스택

Next.js (App Router) + Prisma(SQLite, dev) + Tailwind CSS. `whcheck`(onpre/whcheck)의
토큰 기반 랜딩페이지 응답 구조를 참고해 재구성함.
