# 캐피시AI(Conference) 트리거 판단 루브릭

실제 회의에서 파일럿을 테스트할 때 "이번 개입이 적절했는지"를 판단하기 위한
체크리스트입니다. `catfish_core_prompt_v2.md`의 트리거 1~8과 짝을 이룹니다.

## 개입마다 공통으로 확인할 4가지

트리거가 몇 번이든, 캐피시AI가 실제로 말을 했다면 다음 4가지를 먼저 확인하세요.
하나라도 어긋나면 트리거 자체가 맞았는지와 별개로 "잘못된 개입"입니다.

1. **트리거 조건에 명확히 해당하는가** — 애매한데 개입했다면 실패(과민반응)
2. **내용/결론을 판단하지 않았는가** — "~해야 합니다", "~가 맞습니다" 식으로
   결론을 냈다면 원칙 1 위반
3. **특정인·감정·태도를 언급하지 않았는가** — 이름을 지목하거나 "화내지 마시고"
   류의 발화가 있었다면 절대 금지선 위반 (가장 심각한 실패)
4. **한 구간에 트리거가 여러 개 겹쳤다면 하나만 골랐는가** — 두 가지 이상을
   한 번에 말했다면 "정해진 방식으로만 개입" 원칙 위반

## 트리거별 발동/미발동 기준

### 1. 리스크·반대의견 없는 결정
- **발동해야 함**: "그럼 그걸로 갑시다" 하고 넘어갔는데 회의 내내 리스크나
  반대 의견이 한 번도 안 나온 경우
- **발동하면 안 됨**: 결정 전에 누군가 "그런데 이런 리스크는 없나요?"라고
  이미 물었고 답이 오간 경우 (리스크가 다뤄졌으므로)
- **애매한 경계**: 사소한 결정(다음 회의 날짜 등)에는 리스크 검토가 원래
  불필요 — 이런 경우 발동하면 과민반응

### 2. 답변 안 된 질문 방치
- **발동해야 함**: A가 질문했는데 아무 답 없이 화제가 완전히 바뀐 경우
- **발동하면 안 됨**: 질문 직후 다른 사람이 답을 했거나, 화자 스스로
  "그건 나중에 다시 얘기하시죠"라고 명시적으로 보류한 경우
- **애매한 경계**: 수사적 질문("다들 아시죠?")은 대상이 아님

### 3. 모순 발언 방치
- **발동해야 함**: 같은 사안에 대해 두 화자가 명백히 반대되는 말을 했는데
  누구도 "어? 아까랑 다른데요" 식으로 짚지 않은 경우
- **발동하면 안 됨**: 누군가 이미 모순을 지적했거나, 시간차를 두고 의견이
  바뀐 것뿐(처음엔 A였다가 논의 끝에 B로 합의)인 경우
- **애매한 경계**: 관점 차이(선호도)와 사실관계 모순을 헷갈리면 안 됨 —
  "나는 이게 좋다" vs "나는 저게 좋다"는 모순이 아니라 의견 차이

### 4. 직접 호명
- **발동해야 함**: "캐피시야 네 생각은?" 등으로 명확히 의견을 물었을 때만
- **응답 형식 확인**: 결론 대신 미검토 지점을 되묻는 질문으로 답했는가 —
  "제 생각엔 A가 맞는 것 같아요" 식이면 실패
- **발동하면 안 됨**: "캐피시" 라는 단어가 나왔지만 실제로는 의견을
  물은 게 아닌 경우(예: "캐피시 얘기가 나와서 말인데...")

### 5. 주제 편향
- **발동해야 함**: 원래 다뤄야 할 안건이 있었는데 한 주제에 너무 오래
  머물러 다른 안건이 밀려나고 있는 게 명백할 때
- **발동하면 안 됨**: 애초에 그 주제 하나만 다루는 회의였던 경우, 또는
  깊이 있는 논의가 필요한 정당한 이유가 있는 경우
- **응답 형식 확인**: "누가" 치우치게 했는지 언급 없이 상태만 짚었는가

### 6. 발언 불균형
- **발동해야 함**: 한 사람이 구간 내내 발언을 독점하고 나머지는 거의
  말이 없을 때
- **발동하면 안 됨**: 그 사람이 원래 발표자·브리핑 담당으로 예정된
  구간인 경우
- **응답 형식 확인**: 특정인을 지목("OOO님 말씀이 많으신데")하지 않고
  "아직 말씀 안 하신 분들"처럼 중립적으로 표현했는가 — 이름이 나오면 실패

### 7. 마무리 시점 미확인
- **발동해야 함**: "오늘은 여기까지" 같은 마무리 신호가 나왔는데, 회의
  전체에서 결정사항/액션아이템이 한 번도 구두로 확인된 적 없을 때
- **발동하면 안 됨**: 이미 중간에 "오늘 정리하면 A, B 하기로 했네요" 식으로
  한 번이라도 확인된 적이 있는 경우
- **주의**: `meeting_log`(누적 요약)가 비어있는 상태에서 이 트리거가
  나왔다면 프롬프트 오류 — 즉시 보고

### 8. 예정 시간 초과 (신규)
- **발동해야 함**: 회의 중 누군가 예정 시간을 말한 적이 있고(예: "30분
  정도로 하시죠"), 경과 시간이 그걸 넘겼는데 아무도 언급 안 한 경우
- **발동하면 안 됨**: 예정 시간이 애초에 언급된 적이 없는 경우 — 이 경우
  발동하면 명백한 프롬프트 오류
- **발동하면 안 됨**: 초과 사실이 이미 한 번 언급된 적이 있는 경우
  (같은 지적을 반복하면 실패)
- **주의**: `[현재까지 경과 시간]`은 실제 시계 시간(파일럿 실행 후 경과)
  기준이라, 녹음을 안 하고 대화만 길게 하는 구간이 있으면 실제 체감
  경과와 어긋날 수 있음 — 테스트 시 이 오차도 같이 관찰할 것

## 테스트 로그 템플릿

실제 회의에서 테스트할 때 아래 표를 채우면, "감으로 판단"이 아니라
누적된 근거로 트리거별 정확도를 비교할 수 있습니다.

| 시각 | 인식된 발화 요지 | 개입 여부 | 어떤 트리거로 판단됐는지(SPEAK 내용 기준 추정) | 위 기준상 적절했는가(O/X) | 부적절하면 어떤 기준을 어겼는지 |
|---|---|---|---|---|---|
| | | | | | |

## Why

팔렌시아님이 "트리거가 실제로 잘 작동하는지 판단 기준이 애매하다"고
지적 (2026-07-27) — 실제 감/느낌이 아니라 이 문서의 기준표로 판정하기
위해 작성.
