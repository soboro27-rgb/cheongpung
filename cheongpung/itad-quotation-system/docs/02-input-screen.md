# 02. 입력 화면 UI 사양

## 화면 개요

매각 견적 신규 작성 화면. 영업담당자가 한 화면에서 모든 입력을 완료할 수 있도록 단일 페이지 구성.

**경로**: `/quotations/new`
**권한**: 영업담당자, 팀장, 관리자

## 레이아웃 구조

```
┌─────────────────────────────────────────────────────────┐
│ [헤더] 매각 견적 신규 작성        [임시저장] [견적 산출]  │
├─────────────────────────────────────────────────────────┤
│ [영역 1] 매각 요청 기본정보                              │
│   고객사 | 입찰방식 | 반입예정일 | 반입지역 | 파쇄 | 납기 │
├─────────────────────────────────────────────────────────┤
│ [영역 2] 매각 자산 리스트                                │
│   [엑셀 업로드] [행 추가]                                │
│   ┌─ 업로드 상태 표시 ─┐                                │
│   ┌─ 자산 테이블 (인라인 편집 가능) ─┐                  │
├─────────────────────────────────────────────────────────┤
│ [영역 3] 견적 옵션      │ [영역 4] 견적 미리보기         │
│   목표 마진 슬라이더     │   이력 기준가                  │
│   이력 가중치 선택       │   시세 보정                    │
│   시세 보정 방식         │   처리비용 차감                │
│   리스크 보수율          │   목표 마진 차감               │
│                          │   ───────────                  │
│                          │   제안 견적가 (실시간)         │
└─────────────────────────────────────────────────────────┘
```

## 영역별 상세

### 영역 1: 매각 요청 기본정보

shadcn/ui 컴포넌트: `Card`, `Label`, `Input`, `Select`, `DatePicker`

| 필드 | 컴포넌트 | 검증 | 비고 |
|---|---|---|---|
| 고객사 | Combobox (autocomplete) | 필수 | `Customer` 테이블 검색 |
| 입찰 방식 | Select | 필수 | 공개입찰/지명입찰/수의계약 |
| 반입 예정일 | DatePicker | 필수, 오늘 이후 | |
| 반입 지역 | Select | 필수 | 수도권/충청/영남/호남/강원·제주 |
| 데이터 삭제 | Select | 필수 | 물리파쇄/SW와이핑/없음 |
| 납기 (영업일) | Input number | 1~90 | 기본값 14 |

**고객사 autocomplete 동작**:
- 2글자 이상 입력 시 검색
- 기존 거래 있는 기관 우선 정렬
- 신규 기관은 즉석 등록 가능 (인라인 폼 팝업)

### 영역 2: 매각 자산 리스트

**상단 액션 바**:
- `[엑셀 업로드]` 버튼: 클릭 시 파일 다이얼로그
- `[행 추가]` 버튼: 빈 행 추가
- (선택) `[일괄 삭제]` `[일괄 등급 변경]`

**업로드 상태 표시 (업로드 후)**:
```
[xlsx 아이콘] asset_list_20260512.xlsx · 248행 인식 · 모델 자동매칭 96% 완료  [✓ 정상]
```

상태 색상:
- 정상: green
- 부분 매칭 (70~95%): amber
- 매칭 실패 (<70%): red

**자산 테이블 컬럼**:

| 컬럼 | 너비 | 편집 | 컴포넌트 |
|---|---|---|---|
| 분류 | 60px | 자동 | Badge |
| 모델/스펙 | 가변 | 가능 | Input (자동완성) |
| 연식 | 50px | 가능 | Input number |
| 등급 | 60px | 가능 | Select (A/B/C/?) |
| 수량 | 50px | 가능 | Input number |
| 참고단가 | 80px | 자동 | CurrencyDisplay |
| 매칭 | 70px | 자동 | MatchStatusBadge |

**매칭 상태 표시**:
- `[✓ 18건]` green: 충분한 이력 (10건 이상)
- `[△ 3건]` amber: 이력 부족 (1~9건)
- `[✗ 미매칭]` red: 매칭 실패

**테이블 하단 요약**:
```
총 5개 품목 / 248대   [⚠ 1건 추가 스펙 확인 필요]
```

### 영역 3: 견적 옵션 (좌측)

| 옵션 | 컴포넌트 | 범위 | 기본값 |
|---|---|---|---|
| 목표 마진율 | Slider | 0~30% | 12% |
| 이력 가중치 | Select | 6/12/24개월/전체 | 12개월 |
| 시세 보정 | Select | 자동/국내만/수동 | 자동 |
| 리스크 보수율 | Slider | 0~20% | 5% |

옵션 변경 시 영역 4 미리보기 실시간 재계산 (debounce 300ms).

### 영역 4: 견적 미리보기 (우측)

```
이력 기준가              67,420,000원
시세 보정 (+3.2%)         +2,157,000원
처리비용 차감             -4,200,000원
목표 마진 (12%)           -7,847,000원
─────────────────────────────────
제안 견적가              57,530,000원
신뢰도                   [✓ 높음 (이력 76건)]
```

각 항목은 클릭 시 상세 내역 토글 표시.

## 인터랙션

### 엑셀 업로드 플로우

1. 파일 선택 → 클라이언트에서 SheetJS로 파싱
2. 헤더 자동 인식 시도 (모델/수량/등급/연식 컬럼)
3. 인식 실패 시 컬럼 매핑 다이얼로그 표시
4. 매핑 확정 후 서버 전송 → `AssetMaster` 매칭
5. 매칭 결과 테이블에 표시 (각 행에 매칭 상태)

### 견적 산출 버튼 클릭

1. 모든 필수 필드 검증
2. 미매칭 자산이 있으면 확인 다이얼로그
3. 서버 API `POST /api/quotations` 호출
4. 산출 완료 시 결과 화면 `/quotations/[id]` 으로 이동
5. 실패 시 에러 토스트 + 폼 유지

### 임시저장

- 입력값을 서버에 `status: DRAFT` 로 저장
- 자동 저장: 30초마다 (변경 있을 때만)
- 수동 저장: 버튼 클릭 시 즉시
- 다른 화면 이동 시 변경사항 있으면 확인 다이얼로그

## 검증 규칙 (Zod 스키마)

```typescript
const BidRequestSchema = z.object({
  customerId: z.number().int().positive(),
  bidType: z.enum(['PUBLIC', 'DESIGNATED', 'PRIVATE']),
  pickupDate: z.date().min(new Date()),
  pickupRegion: z.enum(['SEOUL', 'CHUNGCHEONG', 'YEONGNAM', 'HONAM', 'GANGWON_JEJU']),
  dataErasure: z.enum(['PHYSICAL', 'SOFTWARE', 'NONE']),
  leadTimeDays: z.number().int().min(1).max(90),
  assets: z.array(AssetLineSchema).min(1).max(1000),
});

const AssetLineSchema = z.object({
  category: z.enum(['LAPTOP', 'DESKTOP', 'SERVER', 'MONITOR', 'OTHER']),
  rawModelName: z.string().min(1).max(200),
  manufactureYear: z.number().int().min(2000).max(new Date().getFullYear()).optional(),
  grade: z.enum(['A', 'B', 'C', 'UNKNOWN']),
  quantity: z.number().int().positive(),
});
```

## 반응형 동작

- 1280px 이상: 4영역 2×2 그리드 (위 레이아웃 그대로)
- 1024~1279px: 영역 3·4를 영역 2 아래로 이동 (단일 컬럼 부분 적용)
- 1024px 미만: 모바일 미지원 (안내 메시지 표시)

## 접근성

- 모든 폼 요소에 label 연결
- 키보드만으로 전체 입력 가능
- 에러 메시지는 aria-live="polite"
- 색상만으로 상태 구분 금지 (아이콘 병행)

## 화면 구현 우선순위

Phase 4에서 다음 순서로 구현:
1. 영역 1 기본정보 폼 + 검증
2. 영역 2 수기 입력 모드 (행 추가 + 인라인 편집)
3. 영역 2 엑셀 업로드 + 파싱
4. 영역 2 자동 매칭 표시
5. 영역 3 옵션 + 영역 4 미리보기 (실시간 계산)
6. 임시저장 + 자동저장
